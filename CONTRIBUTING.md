# Contributing to AthleteOS

Thank you for helping improve AthleteOS. This project aims to stay useful, professional, and easy to maintain.

## Development Workflow

1. Fork the repository.
2. Create a feature branch from `main`.
3. Keep changes focused and documented.
4. Run `npm test` before opening a pull request.
5. Open a pull request using the template.

## Coding Guidelines

- Preserve existing functionality unless a change is explicitly discussed.
- Keep the app local-first and avoid storing secrets in browser code.
- Prefer small ES modules with descriptive names.
- Use accessible labels, semantic HTML, and keyboard-friendly controls.
- Keep UI states clear for loading, empty data, errors, and success messages.

## Commit Style

Use short imperative commits:

```text
feat: add travel readiness panel
fix: handle empty event source text
docs: update API notes
```

## Review Expectations

Pull requests should explain what changed, why it changed, and how it was tested.
